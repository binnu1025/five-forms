# gas_v2｜新架構的 Apps Script

編輯都在 Google 試算表上做，這支腳本只負責**唯讀**地把資料餵給網頁。
沒有 `doPost`，所以舊版那個「整張覆寫把別場活動清掉」的問題，
在這個架構下不可能發生。

舊版在 `../gas_standalone/`，在切換完成之前**不要刪**——線上的站還在用它。

## 檔案結構

```
總表（一份，永久）           活動清單、人員庫、權限
  ├── 範本｜組員              複製給每一場活動，分享給全部工作人員
  └── 範本｜核心              複製給每一場活動，只分享給核心幹部
```

一場活動 = 兩個檔案。金額只能靠拆檔案隔離——試算表的保護範圍
只能擋編輯，擋不住查看，隱藏分頁任何編輯者都能取消隱藏。

### 組員檔的分頁

| 分頁 | 欄位 |
| --- | --- |
| 細流 | 開始、結束、全體流程，**然後一組一欄** |
| 人力 | 組別、角色、姓名（沒有 Gmail，信箱只留在總表） |
| 物資 | 組別、物資、數量、攜帶者、已還、借出照片、歸還照片、備註 |
| 會議 | 會議名稱、日期 |
| 會後精進 | 組別、下次可以更好的地方、記錄人 |
| 清單 | 給下拉選單用，隱藏 |
| **每一組各一張** | 會議、要完成事項、負責人、目前進度、下一步、期限、狀態 |

### 核心檔的分頁

| 分頁 | 欄位 |
| --- | --- |
| 收支 | 類型、組別、項目、金額、登錄人、備註 |
| 清單 | 隱藏 |

## 內建的下拉選單

資料驗證的「從範圍」**只能參照同一個檔案裡的分頁**，不能跨檔案，
所以每個活動檔案都自帶一張「清單」分頁。

| 分頁 | 欄位 | 選項來源 |
| --- | --- | --- |
| 各組工作 | 狀態 | 進行中／已完成／取消 |
| 各組工作 | 負責人 | 總表人員庫的姓名（建立活動時帶過去） |
| 各組工作 | 會議 | 該檔案「會議」分頁的會議名稱 |
| 物資 | 組別 | 這場活動的組別 |
| 物資 | 已還 | 核取方塊 |
| 人力 | 組別、角色、姓名 | 同上 |
| 會後精進 | 組別 | 同上 |
| 收支 | 類型、組別 | 成本／收入、這場活動的組別 |

## 使用順序

**全部在 `cyp135.ticket@gmail.com` 這個帳號下執行。**

```bash
# 1. 用團隊帳號登入 clasp（會開瀏覽器）
clasp login

# 2. 建立新的 Apps Script 專案
cd gas_v2 && clasp create --type standalone --title "五表 v2"

# 3. 推上去
clasp push
```

然後在 Apps Script 編輯器裡：

1. 執行一次 `建立範本與總表()`
   → 會在雲端硬碟根目錄建好三個檔案，ID 記進指令碼屬性
   （**不寫死在程式碼裡，這個 repo 是公開的**）
2. 把總表的「人員庫」填一填（姓名、雁群小組、Gmail）
3. 把總表的「權限」填一填（Gmail、角色）
4. 每一場活動執行 `開新活動('2026.01 新春團拜', '2026-01-18', '北三教室')`
   → 複製兩份範本、建好每一組的分頁、寫進總表、回傳兩個網址
5. 手動把兩個檔案分享出去（程式刻意不自動加人，免得加錯）

最後 `clasp deploy`，把網址填進 `data.js` 的 `API` 常數。

## 端點

| 請求 | 回傳 |
| --- | --- |
| `GET ?` | 活動清單 ＋ 我是誰 |
| `GET ?event=A001` | 那一場的全部內容，依身分過濾 |

`?who=` 是測試用的後門，正式上線前要拿掉，改用前端送 Google 登入的
`id_token`。

收支的過濾在伺服器端完成：看得到錢的人拿到明細＋總額，組長只拿到
自己那組、沒有總額，其他人拿到 `null`——**核心檔根本不會被讀取**。
